# ADR-034: Integration model, webhooks and storage export

**Status:** Accepted

## Context

Guidelines §54 asks for one integration abstraction (connection,
authentication, capabilities, events, actions, sync), §55 for safe credentials,
§57–§58 for well-formed events and §66 for webhook security. The wedge needs
results to leave Avenra: other systems should learn when work is done, and the
proof of completed work should be filed where the firm keeps records.

## Decision

- **Model.** An organization has *connections*. Each connection has a
  provider, a name, settings (non-secret), credentials (secret, encrypted), a
  status (`ACTIVE`, `PAUSED`, `REVOKED`) and the event types it subscribes
  to. Each provider declares its **capabilities**; the rest of Avenra asks
  for a capability, never for a provider:

  | Provider | Capabilities | Credentials |
  |---|---|---|
  | `WEBHOOK` | `events.deliver` | signing secret (generated by Avenra) |
  | `S3_EXPORT` | `storage.export_completion` | access key and secret key |

  Sync is not used yet (no inbound provider).
- **Credentials (§55).** Sealed with the platform's `SecretBox` (AES-GCM,
  key id, associated data = connection id), stored only as ciphertext,
  returned only once (the webhook secret on creation or rotation), never in
  responses or logs. Rotation replaces the secret; revocation deletes it and
  stops all deliveries.
- **Integration events (§57–§58)** are built from domain events after commit:
  `work.completed`, `information.answer_received`, `request.expired`. Each has
  an id, type, version (`1`), time, organization id and a small payload of
  identifiers and titles; never secrets, document content or answer values.
  Domain, integration and technical events stay separate types.
- **Delivery.** One delivery record per event and connection; a job sends it.
  Retryable failures (network, timeouts, 429, 5xx) back off up to 8 attempts
  over about a day (**product default**); 4xx except 408/429 fail at once.
  After 5 consecutive failed deliveries the connection is paused, audited
  (`integration.connection.paused`) and an `IntegrationEvents.ConnectionPaused`
  fact is published, so the organization's admins are told (notifications,
  Phase 9) (**product default**). Connections belong to the organization, not
  to one work item, so this is not a work exception. A person can resume the
  connection and redeliver.
- **Webhooks (§66).** POST JSON; headers `Avenra-Event-Id`, `Avenra-Event-Type`,
  `Avenra-Signature: t=<unix seconds>,v1=<hex HMAC-SHA256(secret, t + "." +
  body)>`. Receivers check the signature, reject old timestamps (5 minutes is
  recommended) and use the event id for idempotency. No redirects are
  followed; 10-second timeout; response bodies are not stored.
- **Address checks.** Webhook and storage endpoints must be HTTPS; the host is
  resolved at send time and refused if any address is loopback, private,
  link-local, multicast or otherwise not public (SSRF, §63). A setting allows
  plain HTTP to loopback for local development and tests only, and is refused
  in production.
- **Storage export.** On `work.completed`, every active `S3_EXPORT` connection
  receives `<prefix>/<work id>/manifest.json` (the sealed manifest exactly as
  stored) and each accepted document under `documents/`. The export is then
  verified by reading back each object's checksum. An export is one delivery.
- **Permissions.** `integration.read` lists connections and deliveries;
  `integration.manage` creates, changes, tests, rotates, pauses, resumes and
  revokes. Every change is audited.

## Dependencies (§99)

None new: the S3 client is the AWS SDK already used for documents (ADR-019);
HTTP uses the JDK client; HMAC uses the JDK.

## Alternatives

- **One table per provider** — rejected: the common model is the point.
- **Signing with a shared organization key** — rejected: per-connection secrets
  can be rotated without affecting others.

## Consequences

- New providers implement the same interface and declare capabilities.
- Receivers get at-least-once delivery and must deduplicate by event id.
